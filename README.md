# Mattermost Stickers

Простой плагин для Mattermost Team Edition 11.7.3: кнопка возле emoji,
прокручиваемый каталог по пять стикеров в ряд, отправка нажатием и загрузка
PNG системным администратором через настройки плагина. В поставку входит 108 файлов из `stickers/cumemoji_stickers`.

## Установка

1. Включить `PluginSettings.Enable` и `PluginSettings.EnableUploads` на сервере.
2. Открыть **System Console → Plugins → Plugin Management**.
3. Загрузить `dist/ru.senior-sigan.stickers-0.1.4.tar.gz` и включить **Stickers**.
4. При необходимости перезагрузить вкладку или окно Desktop.

Архив содержит серверные бинарники для Linux amd64 и arm64.
Если `RequirePluginSignature` включён, ручная загрузка через консоль недоступна.
Публикация в Marketplace не нужна.

## Поведение

- Стикер отправляется от текущего пользователя как `custom_sigan_sticker` с PNG
  в `file_ids`. В Desktop и браузере плагин рисует оригинальную PNG размером до
  192×192 CSS px: без рамки, фона, панели скачивания и имени файла.
  Текст черновика остаётся на месте. В правой панели отправка идёт в её тред.
- Все авторизованные пользователи, включая гостей, видят общий каталог и могут
  отправлять стикеры. Добавление доступно только системному администратору:
  **System Console → Plugins → Stickers → Каталог стикеров → Добавить PNG**.
  Кнопки загрузки в окне выбора больше нет, в том числе у администраторов.
- На странице настроек можно выбрать несколько статических PNG, до 512 КиБ каждый и 2048×2048 пикселей.
  Сервер проверяет формат и уменьшает большие изображения до **192×192 px**,
  сохраняя пропорции и прозрачность; маленькие изображения не увеличивает.
  Формат изображения всегда PNG. WebP и JPEG не принимаются.
  Одинаковые файлы после нормализации не создают дубликатов.
- Загрузка сохраняет файлы сразу; общую кнопку «Сохранить» нажимать не нужно.
  `POST /stickers` проверяет актуальную роль `system_admin` через серверный API.
  Обычным пользователям, гостям и администраторам команд возвращается HTTP 403,
  даже при прямом обращении к API. После снятия роли администратора загрузка тоже запрещена.
- Загруженные файлы сохраняются в Plugin KV Store Mattermost (PostgreSQL);
  они не зависят от файловой системы контейнера и переживают перезапуск плагина.
  Это простое хранилище для небольшого каталога; поиск, удаление и управление наборами
  в этой версии отсутствуют. Каталог загружается при каждом открытии окна.
- Версия 0.1.2 использует отдельный PNG-каталог. WebP, ранее загруженные через «+»,
  больше не показываются; старые записи остаются в базе без изменений.
  Старые сообщения тоже не меняются — уменьшенный PNG появится при новой отправке.
- Esc и нажатие снаружи закрывают окно. Во время загрузки/отправки действия блокируются.
  При ошибке окно остаётся открытым. После сетевой ошибки проверьте чат перед повтором:
  сервер мог успеть создать сообщение, даже если ответ не дошёл.
- В мобильном приложении остаётся стандартное изображение-вложение.
  Плагин не добавляет туда кнопку выбора и не открывает набор по нажатию.
- Новый внешний вид применяется к сообщениям, отправленным версией 0.1.3.
  Старые обычные сообщения не изменяются автоматически.

## Кастомное сообщение

`registerPostTypeComponent` регистрирует компонент `custom_sigan_sticker`.
Он загружает оригинальный файл через `/api/v4/files/{file_id}`: доступ проверяет
Mattermost по правам пользователя, а история не зависит от каталога плагина.
В `props.stickers` находятся версия схемы, ID/имя стикера, набор и ID вложения.

В Mattermost 11.7.3 список файлов рендерится отдельно от кастомного тела сообщения.
Поэтому узко ограниченный CSS-селектор скрывает стандартную карточку только внутри
того `.post__body`, где наша PNG уже успешно загрузилась. Другие вложения не меняются.
При ошибке загрузки, неизвестной структуре сообщения или выключенном плагине
стандартное вложение остаётся доступным. Эта привязка к DOM также требует проверки
при обновлении Mattermost. Скриншот стенда: `build/custom-sticker-preview.png`.

## Интеграция с редактором

Публичный `registerPostEditorActionComponent` добавляет действие в панель
форматирования. У Mattermost 11.7.3 нет отдельного публичного слота возле emoji.
Поэтому корневой компонент дополнительно вставляет кнопку рядом с
`emojiPickerButton`, следит за пересозданием редактора через MutationObserver
и удаляет её при выключении плагина. Проверены исходники тега `v11.7.3`.

Для этой кнопки поддержаны основной редактор (`post_textbox` в `create_post`)
и правая панель (`reply_textbox` с выбранным постом в Redux).
Контекст определяется заново перед отправкой; неизвестные редакторы не угадываются.
В других редакторах есть штатное действие в панели форматирования, которое получает
точный `draft.channelId` / `draft.rootId` от Mattermost. При скрытой панели
форматирования это запасное действие тоже скрыто. DOM-привязку возле emoji нужно
перепроверять при обновлении Mattermost.

## Сборка и проверки

Нужны Go 1.25+ (точный минимум — в `go.mod`), Node.js 22+ и npm.

```sh
npm ci
go test ./server
npm test
npm run build
npm run test:ui
```

Браузерные тесты используют установленный Google Chrome и локальный стенд
на `127.0.0.1:8766`. Стенд имитирует DOM редактора и ответы REST API;
это не запущенный сервер Mattermost. Скриншот: `build/stickers-preview.png`.
Для одной сборки интерфейса: `node scripts/build.mjs --web-only`.

Сборка копирует исходные PNG без конвертации и формирует установочный архив в `dist/`.
Манифест находится в корне архива; метаданные macOS исключены. Каждая полная сборка
распаковывает архив в Go и проверяет его через `model.FindManifest` Mattermost.
Go SDK закреплён в `go.mod`; React/ReactDOM берутся из Mattermost и не включаются
в production bundle. Зависимости React в npm нужны только браузерному стенду.

## Подготовка набора

Все 108 стикеров уменьшены до 192 px по длинной стороне и сжаты **pngquant 3.0.3**
(`--quality 70-95 --speed 1 --strip`). Размер набора — 1 368 946 байт; до pngquant
эти же уменьшенные PNG занимали 3 747 601 байт (сжатие на 63,5%).
Оригиналы сохранены в `sources/original-webp/` только для воспроизводимости,
в архив плагина они не входят. Отчёт: `sources/conversion-report.json`.

```sh
python3 scripts/prepare-stickers.py --source sources/original-webp --output stickers --size 192
```

Нужны ImageMagick (`magick`) и `pngquant`. PNG, добавленные через админку, уменьшаются
на Go-сервере и кодируются стандартным PNG-кодеком с максимальным сжатием;
pngquant на сервер Mattermost устанавливать не требуется.

У Telegram размер исходного статического стикера — до 512×512 px, с одной стороной
ровно 512 px ([требования](https://core.telegram.org/import-stickers)). Это не
фиксированный размер отображения. 192 px — выбранный компактный размер для нашего
плагина, не утверждение о точном размере во всех клиентах Telegram.

Пользователь подтвердил работу предыдущих версий на сервере. Версия 0.1.4 проверяется
автоматическими тестами и на локальном браузерном стенде; установку новой версии
на настоящий сервер выполняет администратор.
